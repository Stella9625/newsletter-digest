Servo 团队发布了可嵌入的 `servo` crate，开发者利用其构建了网页截图工具，并研究了编译为 WebAssembly 的可行性（发现直接编译不可行，但实现了相关 HTML 解析器的 WASM 版本）。
I set Claude Code for web the task of figuring out what it can do, building a CLI tool for taking screenshots using it and working out if it could be compiled to WebAssembly.
我交给 Claude Code 一项任务：弄清楚这个 crate 能做什么，用它构建一个截图用的 CLI 工具，并研究它是否能编译成 WebAssembly。

Research: Exploring the new servo crate

Servo is now available on crates.io. The Servo team announced the initial release of the servo crate, which packages their browser engine as an embeddable library.

Servo 现已上架 crates.io。Servo 团队宣布了 servo crate（软件包）的初始版本，该版本将他们的浏览器引擎打包为一个可嵌入的库。

I set Claude Code the task of figuring out what it can do, building a CLI tool for taking screenshots using it and working out if it could be compiled to WebAssembly.

我给 Claude Code 布置了一项任务：弄清楚它能做什么，用它构建一个用于截图的 CLI（命令行界面）工具，并研究它是否可以编译为 WebAssembly（WebAssembly）。

The servo-shot Rust tool it built works pretty well:

它构建的 servo-shot Rust 工具运行得相当不错： 

git clone https://github.com/simonw/research
cd research/servo-crate-exploration/servo-shot
cargo build
./target/debug/servo-shot https://news.ycombinator.com/
Here's the result:

结果如下：

Compiling Servo itself to WebAssembly is not feasible due to its heavy use of threads and dependencies like SpiderMonkey, but Claude did build me this playground page for trying out a WebAssembly build of the html5ever and markup5ever_rcdom crates, providing a tool for turning fragments of HTML into a parse tree.

由于 Servo 大量使用了线程以及 SpiderMonkey 等依赖项，将其本身编译为 WebAssembly 是不可行的，但 Claude 确实为我构建了一个 playground（试验场）页面，用于试用 html5ever 和 markup5ever_rcdom crate 的 WebAssembly 构建版本，提供了一个将 HTML 片段转换为解析树的工具。

坎特里尔：论“懒惰”的危机
💡 洞察
Quoting Bryan Cantrill
LLM编程懒惰抽象
Bryan Cantrill 指出，LLMs 因缺乏“懒惰”的美德而不惜堆砌代码，只会让系统愈发臃肿而非精进；这也恰恰反衬出人类因时间有限而追求简洁抽象的“懒惰”是何其珍贵。
The problem is that LLMs inherently lack the virtue of laziness.
问题在于，大语言模型天生缺乏‘懒惰’这一美德。
Left unchecked, LLMs will make systems larger, not better — appealing to perverse vanity metrics, perhaps, but at the cost of everything that matters.
若不加以约束，大语言模型只会让系统变得更大，而非更好——这或许迎合了扭曲的虚荣指标，却以牺牲一切真正重要的东西为代价。

Quoting Bryan Cantrill

The problem is that LLMs inherentlylack the virtue of laziness. Work costs nothing to an LLM. LLMs do not feel a need to optimize for their own (or anyone's) future time, and will happily dump more and more onto a layercake of garbage. Left unchecked, LLMs will make systems larger, not better — appealing to perverse vanity metrics, perhaps, but at the cost of everything that matters.As such, LLMs highlight how essential our human laziness is: our finite timeforcesus to develop crisp abstractions in part because we don't want to waste our (human!) time on the consequences of clunky ones.

问题在于，LLM（大语言模型）本质上缺乏懒惰的美德。工作对 LLM 而言毫无代价。LLM 不会感到有必要为自己（或任何人）的未来时间进行优化，它们会很乐意在一层垃圾蛋糕上不断堆砌。如果不加约束，LLM 会让系统变得更大，而非更好——或许能满足扭曲的虚荣指标（vanity metrics），但却以牺牲一切真正重要的东西为代价。因此，LLM 突显了我们人类懒惰的重要性：我们有限的时间迫使我们去开发清晰的抽象，部分原因就是我们不想把（人类的！）时间浪费在笨拙抽象所带来的后果上。

The problem is that LLMs inherentlylack the virtue of laziness. Work costs nothing to an LLM. LLMs do not feel a need to optimize for their own (or anyone's) future time, and will happily dump more and more onto a layercake of garbage. Left unchecked, LLMs will make systems larger, not better — appealing to perverse vanity metrics, perhaps, but at the cost of everything that matters.

问题在于，LLM 本质上缺乏懒惰的美德。工作对 LLM 而言毫无代价。LLM 不会感到有必要为自己（或任何人）的未来时间进行优化，它们会很乐意在一层垃圾蛋糕上不断堆砌。如果不加约束，LLM 会让系统变得更大，而非更好——或许能满足扭曲的虚荣指标（vanity metrics），但却以牺牲一切真正重要的东西为代价。

As such, LLMs highlight how essential our human laziness is: our finite timeforcesus to develop crisp abstractions in part because we don't want to waste our (human!) time on the consequences of clunky ones.

因此，LLM 突显了我们人类懒惰的重要性：我们有限的时间迫使我们去开发清晰的抽象（abstractions），部分原因就是我们不想把（人类的！）时间浪费在笨拙抽象所带来的后果上。

—Bryan Cantrill, The peril of laziness lost

——Bryan Cantrill，《The peril of laziness lost》（《失去的懒惰之险》）

Gemma 4 audio with MLX

使用 MLX 运行 Gemma 4 音频转录

Thanks to atip from Rahim Nathwani, here's auv runrecipe for transcribing an audio file on macOS using the 10.28 GBGemma 4 E2B modelwith MLX andmlx-vlm:

感谢 Rahim Nathwani 分享的小技巧，以下是一个在 macOS 上使用 uv run 的命令示例，借助 10.28 GB 的 Gemma 4 E2B 模型、MLX 和 mlx-vlm 来转录音频文件：

uv run --python 3.13 --with mlx_vlm --with torchvision --with gradio \
  mlx_vlm.generate \
  --model google/gemma-4-e2b-it \
  --audio file.wav \
  --prompt "Transcribe this audio" \
  --max-tokens 500 \
  --temperature 1.0
