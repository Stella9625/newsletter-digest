AI 网络安全不是工作量证明
💡 洞察
AI cybersecurity is not proof of work
网络安全漏洞挖掘模型智能
作者以OpenBSD SACK漏洞为例论证，AI驱动的网络安全并非“工作量证明”——发现复杂漏洞不取决于算力或采样次数的堆砌，而是受限于模型本身的智能水平；未来该领域的胜负手在于拥有更优质的模型并能更快调用它们。
So, cyber security of tomorrow will not be like proof of work in the sense of "more GPU wins"; instead, better models, and faster access to such models, will win.
因此，未来的网络安全不会像工作量证明那样"GPU 多者胜"；相反，更好的模型，以及更快访问这些模型的能力，才会胜出。
Don't trust who says that weak models can find the OpenBSD SACK bug. I tried it myself.
别相信那些说弱模型能找到 OpenBSD SACK 漏洞的人。我自己试过。

AI cybersecurity is not proof of work

The proof of work is the wrong analogy: finding hash collisions, while exponentially harder with N, is guaranteed to find, with enough work, some S so that H(S) satisfies N, so an asymmetry of resources used will see the side with more "work ability" eventually winning.

proof of work（工作量证明）是一个错误的类比：寻找 hash collisions（哈希碰撞）虽然随着 N 的增长呈指数级困难，但只要投入足够的计算量，就必然能找到某个 S 使得 H(S) 满足 N，因此资源使用的不对称性意味着拥有更多"work ability（工作能力）"的一方最终将获胜。

But bugs are different:
  1. Different LLMs executions take different branches, but eventually the possible branches based on the code possible states are saturated.
  2. If we imagine sampling the model for a bug in a given code M times, with M large, eventually the cap becomes not "M" (because of saturated state of the code AND the LLM sampler meaningful paths), but "I", the model intelligence level.
但漏洞（bugs）的情况不同：
  1. 不同的 LLMs（大语言模型）执行会走不同的分支，但最终基于代码可能状态的所有分支都会达到 saturated（饱和）。
  2. 如果我们想象对模型进行 M 次采样以寻找给定代码中的漏洞，当 M 足够大时，瓶颈最终不再是"M"（因为代码状态已达饱和，且 LLM 采样器的有意义路径也已穷尽），而是"I"，即 model intelligence level（模型智能水平）。
The OpenBSD SACK bug easily shows that: you can run an inferior model for an infinite number of tokens, and it will never realize(*) that the lack of validation of the start window, if put together with the integer overflow, then put together with the fact the branch where the node should never be NULL is entered regardless, will produce the bug.

OpenBSD SACK bug（OpenBSD SACK 漏洞）很好地说明了这一点：你可以用一个较差的模型运行无限多的 tokens（token），但它永远不会意识到（*），如果对起始窗口缺乏验证，再叠加 integer overflow（整数溢出），然后再叠加"无论何种情况都会进入节点本不应为 NULL 的分支"这一事实，就会产生该漏洞。

So, cyber security of tomorrow will not be like proof of work in the sense of "more GPU wins"; instead, better models, and faster access to such models, will win.

因此，未来的网络安全不会像 proof of work（工作量证明）那样意味着"更多 GPU 获胜"；相反，更好的模型以及更快获取这些模型的能力，才是制胜关键。

* Don't trust who says that weak models can find the OpenBSD SACK bug. I tried it myself. What happens is that weak models hallucinate (sometimes causally hitting a real problem) that there is a lack of validation of the start of the window (which is in theory harmless because of the start < end validation) and the integer overflow problem without understanding why they, if put together, create an issue. It's just pattern matching of bug classes on code that looks may have a problem, totally lacking the true ability to understand the issue and write an exploit. Test it yourself, GPT 120B OSS is cheap and available.

* 不要相信那些声称弱模型能发现 OpenBSD SACK bug（OpenBSD SACK 漏洞）的人。我自己试过。实际情况是，弱模型会产生 hallucinate（幻觉）（有时碰巧在因果上撞上一个真实问题），声称缺少对窗口起始位置的验证（这在理论上是无害的，因为有 start < end 的验证）以及存在整数溢出问题，但它并不理解为什么这两者结合起来就会引发问题。这只不过是对可能存在问题的代码进行漏洞类别的 pattern matching（模式匹配），完全缺乏真正理解问题并编写 exploit（漏洞利用程序）的能力。你自己可以测试，GPT 120B OSS 既便宜又容易获取。

BTW, this is why with this bug, the stronger the model you pick (but not enough to discover the true bug), the less likely it is it will claim there is a bug. Stronger models hallucinate less, so they can't see the problem in any side of the spectrum: the hallucination side of small models, and the real understanding side of Mythos.

顺便说一句，这就是为什么对于这个漏洞，你选择的模型越强（但还不足以发现真正的漏洞），它就越不可能声称存在漏洞。更强的模型产生 hallucinate（幻觉）更少，因此它们无法看到光谱中的任何问题：既看不到小模型的 hallucination（幻觉）一侧，也看不到 Mythos 真正理解的一侧。

Why do dLLMs tend to collapse in RL (3 minute read)

Diffusion Language Models (dLLMs) experience training collapse during Reinforcement Learning because their log-likelihood must be estimated using high-variance Monte Carlo sampling, which creates noisy importance ratios. These noisy ratios induce gradient spikes that push policy drift in a positive feedback loop, a problem that traditional AR methods like conditional clipping fail to solve. The newly proposed StableDRL framework stabilizes the update process by combining unconditional clipping to suppress extreme values with self-normalization tied to the effective information in the batch.

扩散语言模型（Diffusion Language Models, dLLMs） 在 强化学习（Reinforcement Learning, RL） 过程中会出现训练崩溃，因为其 log-likelihood 必须使用高方差的蒙特卡洛采样进行估计，这会产生带有噪声的重要性比率（importance ratios）。这些噪声比率会引发梯度尖峰，推动策略漂移形成正反馈循环，而条件裁剪（conditional clipping）等传统的自回归（AR）方法无法解决这一问题。新提出的 StableDRL 框架通过结合无条件裁剪（抑制极端值）和与批次有效信息挂钩的自归一化（self-normalization）来稳定更新过程。
