Honker：为 SQLite 带来队列与流处理的扩展
💡 洞察
russellromney/honker
SQLite消息队列数据库
Honker 是一款专为 SQLite 设计的扩展，它通过简洁的 Python API 和 20 余种自定义 SQL 函数，实现了类 Kafka 的队列与持久化流功能。其核心在于内置事务性发件箱模式，确保消息仅在事务成功提交后才入队，并支持以轮询 WAL 文件的方式实现近实时的消息消费。
The design of this looks very solid.
这个项目的设计看起来非常扎实。
My favorite explanation of that pattern remains Transactionally Staged Job Drains in Postgres by Brandur Leach.
关于该模式，我最推崇的解释依然是 Brandur Leach 撰写的《Transactionally Staged Job Drains in Postgres》。

russellromney/honker

The design of this looks very solid. It lets you write Python code for queues that looks like this: 
import honker

db = honker.open("app.db")
emails = db.queue("emails")
emails.enqueue({"to": "alice@example.com"})

# Consume (in a worker process)
async for job in emails.claim("worker-1"):
    send(job.payload)
    job.ack()

Serving the For You feed

为你推荐（For You）信息流的服务架构

spacecowboy runs theFor You Feed, used by around 72,000 people. This guest post on the AT Protocol blog explains how it works.

spacecowboy 运营着 For You Feed（为你推荐信息流），服务于约 72,000 名用户。这篇发布在 AT Protocol（AT 协议）博客上的客座文章解释了它的工作原理。

The architecture isfascinating. The feed is served by a single Go process using SQLite on a "gaming" PC in spacecowboy's living room - 16 cores, 96GB of RAM and 4TB of attached NVMe storage.

其架构设计令人着迷。该信息流由一台在 spacecowboy 客厅“游戏”PC 上运行的单 Go 语言进程通过 SQLite 提供服务——这台电脑配备 16 核 CPU、96GB 内存以及 4TB 外接 NVMe 存储。

Recommendations are based on likes: what else are the people who like the same things as you liking on the platform?

Recommendations（推荐内容）基于 likes（点赞）：与你喜好相似的人还在平台上点赞了哪些内容？

That Go server consumes the Bluesky firehose and stores the relevant details in SQLite, keeping the last 90 days of relevant data, which currently uses around 419GB of SQLite storage.

这台 Go server（Go 服务器）消费 Bluesky 的 firehose（实时全量数据流），并将相关详情存入 SQLite，仅保留最近 90 天的相关数据，目前约占用了约 419GB 的 SQLite 存储空间。

Public internet traffic is handled by a $7/month VPS on OVH, which talks to the living room server via Tailscale.

公网流量由一台每月 7 美元的 VPS（虚拟专用服务器，托管于 OVH）处理，它通过 Tailscale 与客厅中的服务器通信。

Total cost is now $30/month: $20 in electricity, $7 in VPS and $3 for the two domain names. spacecowboy estimates that the existing system could handle all ~1 million daily active Bluesky users if they were to switch to the cheapest algorithm they have found to work.

目前的总成本为每月 30 美元：20 美元电费、7 美元 VPS 费用以及 3 美元的两个域名费用。spacecowboy 估计，如果切换到他们发现的成本最低的可用 algorithm（算法），现有系统足以承载全部约 100 万 Bluesky 日活跃用户。
