MacBook Neo的软件摄像头指示灯运行在芯片安全隔离区（secure exclave）中，安全性堪比硬件指示灯，即使遭遇内核级漏洞攻击也无法绕过该指示灯秘密启用摄像头。
What that means in practice is that even a kernel-level exploit would not be able to turn on the camera without the light appearing on screen.
这在实践中意味着，即使是内核级漏洞也无法在指示灯不亮的情况下打开摄像头。
Tidbit: the software-based camera indicator light in the MacBook Neo runs in the secure exclave1 part of the chip, so it is almost as secure as the hardware indicator light. What that means in practice is that even a kernel-level exploit would not be able to turn on the camera without the light appearing on screen. It runs in a privileged environment separate from the kernel and blits the light directly onto the screen hardware.

小知识：MacBook Neo 的软件相机指示灯运行在芯片的 secure exclave（安全隔离区）1 部分，因此其安全性几乎与硬件指示灯相当。这在实际中意味着，即使是内核级漏洞（kernel-level exploit）也无法在指示灯不亮的情况下启动摄像头。它运行在与内核隔离的特权环境（privileged environment）中，并直接将指示灯图像位块传输（blit）到屏幕硬件上。

编程智能体的工作原理
💡 洞察
How coding agents work
编程智能体LLM工具调用
编码智能体通过系统提示和工具调用扩展大语言模型的能力，其核心是LLM与工具在循环中持续交互，使AI能够自主执行代码编写、调试等复杂任务。
A coding agent is a piece of software that acts as a harness for an LLM, extending that LLM with additional capabilities that are powered by invisible prompts and implemented as callable tools.
编程智能体是一种充当LLM套件的软件，通过隐形提示词驱动并以可调用工具的形式实现，从而扩展该LLM的额外能力。
A good tool loop is a great deal more work than that, but the fundamental mechanics are surprisingly straightforward.
构建一个出色的工具循环远比这复杂，但其基本机制却出人意料地简单明了。

Agentic Engineering Patterns

As with any tool, understanding howcoding agentswork under the hood can help you make better decisions about how to apply them.

与任何工具一样，理解 coding agents（编程智能体）的底层工作原理有助于你更好地决定如何应用它们。

A coding agent is a piece of software that acts as aharnessfor an LLM, extending that LLM with additional capabilities that are powered by invisible prompts and implemented as callable tools.

Coding agent（编程智能体）是一种充当 LLM（Large Language Model，大语言模型）harness（承载框架）的软件，通过不可见的提示词（prompts）为 LLM 扩展额外能力，并以可调用工具（callable tools）的形式实现这些能力。

Large Language Models

At the heart of any coding agent is a Large Language Model, or LLM. These have names like GPT-5.4 or Claude Opus 4.6 or Gemini 3.1 Pro or Qwen3.5-35B-A3B.

任何编程智能体的核心都是 Large Language Model（大语言模型，简称 LLM）。这些模型有着诸如 GPT-5.4、Claude Opus 4.6、Gemini 3.1 Pro 或 Qwen3.5-35B-A3B 等名称。

An LLM is a machine learning model that can complete a sentence of text. Give the model the phrase "the cat sat on the " and it will (almost certainly) suggest "mat" as the next word in the sentence.

LLM 是一种能够补全文本句子的机器学习模型。给模型输入短语 "the cat sat on the "，它（几乎肯定）会建议将 "mat" 作为句子的下一个词。

As these models get larger and train on increasing amounts of data, they can complete more complex sentences - like "a python function to download a file from a URL is def download_file(url): ".

随着这些模型规模越来越大，并在越来越多的数据上进行训练，它们能够补全更复杂的句子——例如 "a python function to download a file from a URL is def download_file(url): "。

LLMs don't actually work directly with words - they work with tokens. A sequence of text is converted into a sequence of integer tokens, so "the cat sat on the " becomes[3086, 9059, 10139, 402, 290, 220]. This is worth understanding because LLM providers charge based on the number of tokens processed, and are limited in how many tokens they can consider at a time.

LLM 实际上并不直接处理单词——它们处理的是 tokens（词元）。一段文本序列会被转换成整数词元序列，因此 "the cat sat on the " 会变成 [3086, 9059, 10139, 402, 290, 220]。理解这一点很重要，因为 LLM 提供商根据处理的词元数量收费，并且模型一次能处理的词元数量也有限制。

You can experiment with the OpenAI tokenizer to see how this works atplatform.openai.com/tokenizer.

你可以在 OpenAI 的分词器（tokenizer）上实验这一机制，网址是 platform.openai.com/tokenizer。

The input to an LLM is called theprompt. The text returned by an LLM is called thecompletion, or sometimes theresponse.

输入给 LLM 的内容称为 prompt（提示词）。LLM 返回的文本称为 completion（补全），有时也称为 response（响应）。

Many models today aremultimodal, which means they can accept more than just text as input.Vision LLMs(vLLMs) can accept images as part of the input, which means you can feed them sketches or photos or screenshots. A common misconception is that these are run through a separate process for OCR or image analysis, but these inputs are actually turned into yet more token integers which are processed in the same way as text.

如今许多模型都是 multimodal（多模态）的，这意味着它们不仅能接受文本作为输入。Vision LLMs（视觉大语言模型，简称 vLLMs）可以将图像作为输入的一部分，这意味着你可以向它们提供草图、照片或截图。一个常见的误解是这些图像会通过单独的 OCR 或图像分析流程处理，但实际上这些输入会被转换成更多的整数词元，并以与文本相同的方式处理。

Chat templated prompts

The first LLMs worked as completion engines - users were expected to provide a prompt which could then be completed by the model, such as the two examples shown above.

最初的 LLM 充当补全引擎（completion engines）工作——用户需要提供一个提示词，然后由模型来补全，就像上面展示的两个例子那样。

This wasn't particularly user-friendly so models mostly switched to usingchat templated promptsinstead, which represent communication with the model as a simulated conversation.

这种方式对用户并不特别友好，因此模型大多转而使用 chat templated prompts（聊天模板提示词），将模型交互模拟成一场对话。

This is actually just a form of completion prompt with a special format that looks something like this. 
user: write a python function to download a file from a URL
assistant:

这其实只是补全提示词的一种特殊格式，看起来大致如下。

The natural completion for this prompt is for the assistant (represented by the LLM) to answer the user's question with some Python code.

对于这个提示词，自然的补全方式是助手（由 LLM 代表）用一段 Python 代码回答用户的问题。

LLMs are stateless: every time they execute a prompt they start from the same blank slate.

LLM 是无状态的（stateless）：每次执行提示词时，它们都从相同的空白状态开始。

To maintain the simulation of a conversation, the software that talks to the model needs to maintain its own state and replay the entire existing conversation every time the user enters a new chat prompt: 
user: write a python function to download a file from a URL
assistant: def download_url(url):
    return urllib.request.urlopen(url).read()
user: use the requests library instead
assistant:

为了维持对话的模拟效果，与模型交互的软件需要自己维护状态，并在用户每次输入新的聊天提示词时，重新播放整个已有的对话记录：

Since providers charge for both input and output tokens, this means that as a conversation gets longer, each prompt becomes more expensive since the number of input tokens grows every time.

由于提供商对输入和输出的词元都收费，这意味着随着对话变长，每次提示词都会变得更昂贵，因为输入词元的数量每次都在增加。

Token caching

Most model providers offset this somewhat through a cheaper rate forcached input tokens- common token prefixes that have been processed within a short time period can be charged at a lower rate as the underlying infrastructure can cache and then reuse many of the expensive calculations used to process that input.

大多数模型提供商通过为 cached input tokens（缓存输入词元）提供更低的费率来在一定程度上抵消这一成本——在短时间内已处理的常见词元前缀可以按更低费率计费，因为底层基础设施可以缓存并重复使用许多用于处理该输入的昂贵计算。

Coding agents are designed with this optimization in mind - they avoid modifying earlier conversation content to ensure the cache is used as efficiently as possible.

Coding agents（编程智能体）在设计时就考虑到了这一优化——它们避免修改早期的对话内容，以确保缓存能够被尽可能高效地利用。

Calling tools

The defining feature of an LLMagentis that agents can calltools. But what is a tool?

LLM agent（LLM 智能体）的决定性特征是智能体能够调用 tools（工具）。但什么是工具呢？

A tool is a function that the agent harness makes available to the LLM.

工具是智能体承载框架（agent harness）向 LLM 提供的一个函数。

At the level of the prompt itself, that looks something like this: 
system: If you need to access the weather, end your turn with get_weather(city_name)
user: what's the weather in San Francisco?
assistant:

在提示词层面，它看起来大致如下：

Here the assistant might respond with the following text: 
get_weather("San Francisco")

在这种情况下，助手可能会用以下文本回应：

The model harness software then extracts that function call request from the response - probably with a regular expression - and executes the tool.

随后，模型承载框架软件会从响应中提取该函数调用请求——可能是通过正则表达式——并执行该工具。

It then returns the result to the model, with a constructed prompt that looks something like this: 
system: If you need to access the weather, end your turn with get_weather(city_name)
user: what's the weather in San Francisco?
assistant: get_weather("San Francisco")
user: 61°, Partly cloudy
assistant:

然后它将结果返回给模型，并构造一个看起来大致如下的提示词：

The LLM can now use that tool result to help generate an answer to the user's question.

LLM 现在可以利用该工具结果来帮助生成对用户问题的回答。

Most coding agents define a dozen or more tools for the agent to call. The most powerful of these allow for code execution - aBash()tool for executing terminal commands, or aPython()tool for running Python code, for example.

大多数编程智能体定义了十几个或更多的工具供智能体调用。其中最强大的工具允许代码执行——例如一个用于执行终端命令的 Bash() 工具，或一个用于运行 Python 代码的 Python() 工具。

The system prompt

In the previous example I included an initial message marked "system" which informed the LLM about the available tool and how to call it.

在上面的例子中，我包含了一条标记为 "system" 的初始消息，它告知 LLM 有哪些可用工具以及如何调用它们。

Coding agents usually start every conversation with a system prompt like this, which is not shown to the user but provides instructions telling the model how it should behave.

编程智能体通常在每次对话开始时都使用这样的 system prompt（系统提示词），这不会展示给用户，但会向模型提供指令，告诉它应该如何表现。

These system prompts can be hundreds of lines long. Here'sthe system prompt for OpenAI Codexas-of March 2026, which is a useful clear example of the kind of instructions that make these coding agents work.

这些系统提示词可能长达数百行。这是截至 2026 年 3 月 OpenAI Codex 的系统提示词，它是让这类编程智能体运作的指令类型的一个有用且清晰的示例。

Reasoning

One of the big new advances in 2025 was the introduction ofreasoningto the frontier model families.

2025 年的重大进展之一是将 reasoning（推理能力）引入前沿模型家族。

Reasoning, sometimes presented asthinkingin the UI, is when a model spends additional time generating text that talks through the problem and its potential solutions before presenting a reply to the user.

Reasoning（推理）有时在界面上呈现为 thinking（思考），是指模型在向用户呈现回复之前，花费额外时间生成文本来梳理问题及其潜在解决方案的过程。

This can look similar to a person thinking out loud, and has a similar effect. Crucially it allows models to spend more time (and more tokens) working on a problem in order to hopefully get a better result.

这可能看起来类似于一个人在大声思考，并且具有类似的效果。关键的是，它允许模型花费更多时间（和更多词元）来处理问题，以期获得更好的结果。

Reasoning is particularly useful for debugging issues in code as it gives the model an opportunity to navigate more complex code paths, mixing in tool calls and using the reasoning phase to follow function calls back to the potential source of an issue.

Reasoning（推理）对于调试代码问题特别有用，因为它给了模型机会去遍历更复杂的代码路径，混合使用工具调用，并利用推理阶段追溯函数调用回到问题的潜在根源。

Many coding agents include options for dialing up or down the reasoning effort level, encouraging models to spend more time chewing on harder problems.

许多编程智能体包含调节推理努力程度的选项，鼓励模型在更难的问题上花费更多时间深入思考。

LLM + system prompt + tools in a loop

Believe it or not, that's most of what it takes to build a coding agent!

信不信由你，构建一个编程智能体所需的要素大致就是这些！

If you want to develop a deeper understanding of how these things work, a useful exercise is to try building your own agent from scratch. A simple tool loop can be achieved with a few dozen lines of code on top of an existing LLM API.

如果你想深入理解这些事物的工作原理，一个有用的练习是尝试从头构建你自己的智能体。一个简单的工具循环（tool loop）只需在现有 LLM API 的基础上用几十行代码就能实现。

Agoodtool loop is a great deal more work than that, but the fundamental mechanics are surprisingly straightforward.

It enables networks to selectively retrieve past representations, naturally mitigating dilution and hidden-state growth. Attention Residuals have been validated on the Kimi Linear architecture, demonstrating consistent downstream performance gains.

残差连接长期依赖固定的均匀累积。Attention Residuals（注意力残差）用对前层的学习型、输入依赖注意力取代了标准的深度递归。它使网络能够选择性检索过去的表示，自然缓解稀释和隐藏状态增长问题。注意力残差已在 Kimi Linear 架构上得到验证，显示出持续的下游性能提升。

Agentic Engineering Patterns

I use the term agentic engineering to describe the practice of developing software with the assistance of coding agents.

我使用agentic engineering（代理工程）这个术语来描述在coding agents（编程代理）协助下开发软件的实践。

What are coding agents? They're agents that can both write and execute code. Popular examples include Claude Code, OpenAI Codex, and Gemini CLI.

什么是coding agents（编程代理）？它们是既能编写又能执行代码的代理。流行的例子包括Claude Code、OpenAI Codex和Gemini CLI。

What's an agent? Clearly defining that term is a challenge that has frustrated AI researchers since at least the 1990s but the definition I've come to accept, at least in the field of Large Language Models (LLMs) like GPT-5 and Gemini and Claude, is this one:

什么是agent（代理）？清晰定义这个术语是一项挑战，自1990年代以来就一直困扰着人工智能研究者，但我已接受的定义是——至少在LLMs（Large Language Models，大语言模型）领域，如 GPT-5、Gemini 和 Claude——如下：

The "agent" is software that calls an LLM with your prompt and passes it a set of tool definitions, then calls any tools that the LLM requests and feeds the results back into the LLM.

"Agent（代理）"是一种软件，它用你的提示词（prompt）调用LLM（大语言模型），并传递一组工具定义给模型，然后调用 LLM 请求的任何工具，并将结果反馈回 LLM。

For coding agents, those tools include one that can execute code.

对于coding agents（编程代理），这些工具包含能够执行代码的工具。

You prompt the coding agent to define a goal. The agent then generates and executes code in a loop until that goal has been met.

你提示编程代理定义一个目标。然后该代理在循环中生成并执行代码，直到达成该目标。

Code execution is the defining capability that makes agentic engineering possible. Without the ability to directly run the code, anything output by an LLM is of limited value. With code execution, these agents can start iterating towards software that demonstrably works.

代码执行是使agentic engineering（代理工程）成为可能的决定性能力。没有直接运行代码的能力，LLM 输出的任何内容价值都有限。有了代码执行能力，这些代理就能开始迭代，朝着确实可用的软件迈进。

Agentic engineering

Now that we have software that can write working code, what is there left for us humans to do?

现在我们有了能够编写可用代码的软件，我们人类还有什么可做的呢？

The answer is so much stuff.

答案是还有很多事情要做。

Writing code has never been the sole activity of a software engineer. The craft has always been figuring out what code to write. Any given software problem has dozens of potential solutions, each with their own tradeoffs. Our job is to navigate those options and find the ones that are the best fit for our unique set of circumstances and requirements.

编写代码从来不是软件工程师的唯一活动。这门手艺始终是在弄清楚该写什么代码。任何给定的软件问题都有数十种潜在的解决方案，每种都有其自身的权衡取舍。我们的工作是在这些选项中导航，找到最适合我们独特情况和需求的方案。

Getting great results out of coding agents is a deep subject in its own right, especially now as the field continues to evolve at a bewildering rate.

从coding agents（编程代理）获得出色结果本身就是一个深奥的课题，尤其是现在该领域正以令人眩晕的速度持续发展。

We need to provide our coding agents with the tools they need to solve our problems, specify those problems in the right level of detail, and verify and iterate on the results until we are confident they address our problems in a robust and credible way.

我们需要为编程代理提供解决问题所需的工具，以适当的详细程度明确这些问题，并验证和迭代结果，直到我们确信它们以稳健且可信的方式解决了我们的问题。

LLMs don't learn from their past mistakes, but coding agents can, provided we deliberately update our instructions and tool harnesses to account for what we learn along the way.

LLMs（大语言模型）不会从过去的错误中学习，但coding agents（编程代理）可以——前提是我们有意识地更新指令和工具套件，以考虑我们沿途学到的经验。

Used effectively, coding agents can help us be much more ambitious with the projects we take on. Agentic engineering should help us produce more, better quality code that solves more impactful problems.

如果有效使用，编程代理可以帮助我们在承担的项目上变得更加雄心勃勃。Agentic engineering（代理工程）应该帮助我们产出更多、更高质量的代码，解决更有影响力的问题。

Isn't this just vibe coding?

The term "vibe coding" was coined by Andrej Karpathy in February 2025 - coincidentally just three weeks prior to the original release of Claude Code - to describe prompting LLMs to write code while you "forget that the code even exists".

"vibe coding"这一术语由Andrej Karpathy于2025年2月创造——巧合的是，就在Claude Code最初发布的三周前——用来描述在提示 LLM 编写代码时"忘记代码甚至存在"的状态。

Some people extend that definition to cover any time an LLM is used to produce code at all, but I think that's a mistake. Vibe coding is more useful in its original definition - we need a term to describe unreviewed, prototype-quality LLM-generated code that distinguishes it from code that the author has brought up to a production ready standard.

有些人扩展了这一定义，涵盖任何使用 LLM 生成代码的情况，但我认为这是一个错误。Vibe coding在其原始定义中更有用——我们需要一个术语来描述未经审查的、原型质量的 LLM 生成代码，以将其与作者提升到生产就绪标准（production ready）的代码区分开来。
