CSP Allow-list Experiment
CSP沙箱白名单
该实验展示了一种在CSP保护的沙盒iframe中动态管理外部请求的方案：通过自定义fetch()拦截连接错误并上报父窗口，从而提示用户将受阻域名添加至允许列表并刷新页面。该工具由作者使用GPT-5.5 xhigh在Codex桌面应用中开发。
An experiment that shows that you can load an app in a CSP-protected sandboxed iframe and have a custom fetch() that intercepts CSP errors and passes them up to the parent window... which can then prompt the user to add that domain to an allow-list and then refresh the page.
一项实验表明，你可以在受 CSP 保护的沙盒 iframe 中加载应用，并通过自定义 fetch() 拦截 CSP 错误，将其传递给父窗口……父窗口随后可提示用户将该域名添加到白名单并刷新页面。

该实验展示了如何在一个受 CSP（内容安全策略）保护的 sandboxed iframe（沙盒 iframe，参见前文）中加载应用，并通过自定义的 fetch() 方法拦截 CSP 错误，将其上报给 parent window（父窗口）……随后父窗口可提示用户将该域名添加至 allow-list（允许列表），并刷新页面。

That segfault bug wasgnarly. I added a mechanism to Datasette recently that would automatically close connections at the end of each test, but it turned out that introduced a race condition where an in-flight query could sometimes be executing in a thread against a connection while it was being closed. I ended up solving that by having Codex CLI (with GPT-5.5 xhigh) createa minimal Dockerfilethat recreated the bug.

那个 segfault（段错误）缺陷非常棘手。我最近为 Datasette 添加了一个机制，可以在每次测试结束时自动关闭连接，但结果这引入了 race condition（竞态条件）：有时一个正在执行的查询可能正在某个线程中针对连接运行，而与此同时该连接正在被关闭。我最终通过让 Codex CLI（配合 GPT-5.5 xhigh）创建一个最小化的 Dockerfile 来重现该缺陷，从而解决了这个问题。
